Gradient boosting, a worked example with 8 customers

The idea in one line: start with a rough guess, measure how wrong it is for each customer, add a small decision tree that corrects those mistakes, and repeat.

All numbers below are calculated, not illustrative. The example is simplified: the real model works on the log-odds scale, uses larger trees and runs 300–400 rounds with smaller steps.

3 of the 8 customers churned.

Step 0: start with the simplest guess

Give everyone the average churn rate, 3 ÷ 8 = 0.375, so a 37.5% predicted risk for every customer.

Step 1: measure the mistakes (the "residuals")

Mistake = what actually happened − what we predicted. Churned counts as 1, retained as 0.

Customer Actual Predicted Mistake
A, B, C (churned) 1 0.375 +0.625, too low
D, E, F, G, H (stayed) 0 0.375 −0.375, too high

Step 2: tree 1, find the question that best sorts the mistakes

The model tries possible yes/no questions and keeps the one that best separates the "too low" mistakes from the "too high" ones:

Tree 1: "Is any member on DTC?"
YES (E, F, G): average mistake −0.375, so these predictions are too high
NO (A, B, C, D, H): average mistake +0.225, so these predictions are too low

Step 3: take a small step in that direction

New prediction = old prediction + learning rate × the tree's correction. The learning rate here is 0.5, which means the model only moves halfway, so no single tree can overreact.

Group Calculation New prediction
DTC users (E, F, G) 0.375 + 0.5 × (−0.375) 0.188
Non-DTC (A, B, C, D, H) 0.375 + 0.5 × (+0.225) 0.488

Step 4: repeat, and tree 2 picks up what tree 1 missed

New mistakes: A, B and C are still too low (+0.512), while D and H are now too high (−0.488). Tree 1 can't separate these, because none of them use DTC. So tree 2 asks a different question:

Tree 2: "Silent for more than 14 days?"
YES (A, B, F): average mistake +0.279, push up
NO (C, D, E, G, H): average mistake −0.168, push down
Customer After tree 1 Tree 2's step After tree 2
A, B (silent, no DTC) 0.488 +0.140 0.627
C, D, H (reporting, no DTC) 0.488 −0.084 0.404
F (silent, but uses DTC) 0.188 +0.140 0.327
E, G (reporting, use DTC) 0.188 −0.084 0.104

What happened: - Silent customers without DTC (A, B) rose to the highest risk. - DTC users who keep reporting (E, G) fell to almost zero. - F (silent, but uses DTC) landed in between. The trees combined the two signals, which is the "interaction" a points-based score can't capture. - C, D and H look identical in this data (reporting, no DTC), so the model can't tell them apart. It gives all three the same middle risk. No model can beat the information it's given.

Why it's called "gradient" boosting

Each tree is fitted to the mistakes (actual − predicted). Those mistakes are exactly the downhill direction of the error, so every round is one step of gradient descent: walking downhill on the error, one small tree at a time.

Why we didn't pick it in the end: with this much data, all those trees weren't significantly more accurate than the simple 3-parameter logistic model (average AUC 0.859 vs 0.842). The logistic model can be explained in one sentence per customer.
